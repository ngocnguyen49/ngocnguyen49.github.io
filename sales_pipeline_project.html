PROJECT: SALES ANALYTICS PIPELINE

AWS S3 → SNOWFLAKE → POWER BI || END-TO-END DATA PIPELINE

Snowflake Power BI SQL AWS S3 Data Quality

Background Information

In modern cloud data architectures, building reliable and scalable pipelines requires decoupling storage from compute while strictly maintaining data quality. This project demonstrates an enterprise-grade, cloud-native data pipeline that ingests raw retail sales CSV files stored in an Amazon S3 bucket, runs pre-load validation, transforms data across a multi-tier Medallion Architecture inside Snowflake, and delivers business metrics through Power BI.

To prevent malformed data from corrupting downstream models, automated Python validation runs prior to loading, checking schema consistency and critical integrity constraints. Validated data is then loaded into Snowflake and processed across three isolated layers: Bronze (immutable raw staging), Silver (cleansed, typed, and quality-tested data), and Gold (business-level aggregations engineered for BI reporting).

Reflecting industry best practices for cloud data warehousing and data lakehouse governance, this workflow highlights how leveraging S3 staging, Python validation scripts, modular SQL transformation layers, and BI tools delivers a robust, single source of truth for decision-makers.

Objective

The goal is to build an automated, cloud-native data pipeline that ingests raw CSV files stored in an AWS S3 External Stage into a Snowflake Data Warehouse. This end-to-end architecture replaces fragile manual loads with an enterprise Medallion Architecture, ensuring high data quality, automated governance, and high-performance reporting.

  • Pre-Load Validation: Execute automated Python scripts (00_pre_load_validation.py) to catch schema mismatches and malformed records before ingestion.
  • S3 External Staging & Bronze Ingestion: Connect Snowflake directly to AWS S3 via storage integrations for seamless ingestion into raw staging (01_setup_and_load.sql).
  • Medallion SQL Transformations: Programatically clean, type-cast, and execute data quality tests across Silver (02_transform_and_quality.sql) and Gold (03_aggregations.sql) layers.
  • BI Optimization: Deliver high-speed, business-ready aggregations to Power BI using optimized Import Mode.

Chapter 1: Bronze Layer (Raw Ingestion & Dynamic Schema)

The Bronze layer serves as an immutable landing zone inside Snowflake. Data is dynamically ingested directly from an Amazon S3 External Stage using automated schema inference, preserving raw fidelity while capturing ingestion audit metadata.

  • Pre-Load Validation: Executes automated Python scripts (00_pre_load_validation.py) to verify raw file structure and catch integrity errors prior to loading.
  • S3 External Stage Integration: Connects Snowflake directly to the raw S3 bucket using CREATE STAGE with authenticated IAM credentials.
  • Dynamic Schema Inference: Leverages Snowflake's INFER_SCHEMA and USING TEMPLATE functions to dynamically construct the raw_orders table without manual column definitions.
  • Flexible Bulk Ingestion: Ingests source data via COPY INTO using MATCH_BY_COLUMN_NAME = CASE_INSENSITIVE to safely handle varying CSV header orders.
  • Audit Lineage: Appends a _loaded_at timestamp metadata column to establish data lineage for downstream processing.

Chapter 2: Silver Layer (Transformation & Data Quality)

The Silver layer cleanses, standardizes, and validates Bronze data to construct a trusted fact_orders table. Prior to materialization, an automated data quality scorecard executes inside Snowflake to enforce business integrity constraints.

  • Automated Quality Scorecard: Runs multi-point SQL validation checks verifying row counts, strict non-null values for key business fields, date ranges, and zero negative sales.
  • Data Cleansing & Standardizing: Applies string trimming across text fields, converts text flags to booleans (is_returned), and enforces proper data types for dates and numeric values.
  • Derived Metrics Engineering: Calculates operational metrics inline, including days_to_ship, profit_margin_pct, and extracted order_year / order_month attributes.
  • Staging View to Fact Materialization: Encapsulates logic inside a staging view (stg_orders) before materializing into a high-performance fact_orders table for downstream Gold layer aggregations.
